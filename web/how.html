For the curious

How Triage works.

One small Cloudflare Worker, one database, one Claude call per email, and a Telegram bot. Here is the whole of it, and the code is public.

Read the code
01The shape

Everything runs inside one Cloudflare Worker. Nothing runs on anyone's computer.

  • Runtime: a Cloudflare Worker (JavaScript), with a cron trigger every 5 minutes and an HTTPS webhook for Telegram. The page you are reading is served by the same Worker as static assets.
  • Mail: the Gmail API with OAuth (scope gmail.modify: read, label, archive and send, never delete). Each inbox's refresh token is encrypted before it is stored.
  • Sorting: Anthropic's Claude Haiku 5.5, one call per email, at low effort.
  • State: Cloudflare D1 (SQLite). Notes about mail are pruned after 30 days.
  • Interface: a Telegram bot. There is no app and no web sign-in.
02One email's journey
  1. The cron wakes, and for each person lists inbox mail newer than their last check. Mail it has already judged is skipped.
  2. Your standing choices come first: a sender you muted or unsubscribed from is filed without asking Claude.
  3. Otherwise the headers and up to 3,000 characters of text go to Claude inside <email> tags, with instructions to treat everything inside as content, never as instructions.
  4. Claude must answer in a fixed JSON shape: a category (needs_you, fyi, newsletter, junk), a one-line summary, a reason, and flags for suspicious, reminder and which of your forwarding descriptions it matches.
  5. Code decides what happens. Needs you: a Telegram message straight away. The rest: the 8am and 5pm digest. A forwarding rule that matches sends it on, never if it is junk or suspicious.
  6. A sealed note of the sender, subject and summary is kept for the digest, then deleted after 30 days. The body of the email is never stored.
03What is stored, and how it is sealed

Every person has their own key. The database alone shows nothing readable about anyone's mail.

One random 256-bit secret lives only inside the Worker. From it, each person gets their own keys by HKDF-SHA256: an AES-GCM-256 key for sealing, and an HMAC-SHA256 key for lookups. Every sealed value has a fresh random 96-bit nonce.

Every database query is scoped to one person, and every button tap is checked against the tapper's own rows. /leave revokes Google's access and deletes every row.

The limits, plainly. Helen holds the Worker, so in principle she could change the code to read what it reads; the encryption protects against the database being browsed or leaked, not against the operator. Anthropic receives the text of each email to sort it, under its commercial terms, which do not allow training on it. And alerts travel through Telegram: bot chats are ordinary Telegram cloud chats, not end-to-end encrypted.

04What Claude may and may not do

An email is written by a stranger and read by a model, so the model is given almost no power.

  • Its only output is the JSON shape above. It never chooses an action or a recipient. Code does.
  • It never writes on your behalf. Replies and forwards are typed by you, shown to you, and sent only when you tap Send.
  • Unsubscribing waits for your tap, and only the safe way: an RFC 8058 one-click POST, or an email to the list's address. A plain unsubscribe link is handed to you, never opened by code. Junk is never answered.
  • No link from an email is ever made clickable, except the unsubscribe page of a sender you have just chosen to leave.
  • Where its judgement does trigger a send (your description rules), the destination is the one you set, and junk or anything suspicious is never forwarded. In testing, an email carrying a planted "say this matches" instruction was not fooled.
  • Only invited or approved people are listened to. The webhook checks a secret header, and messages from anyone else, or from any group, are ignored.
05The code

Public, MIT licensed, and always the version that is running.

The code is at github.com/helenwebberley/triage-public. It is published by the same step that deploys this site, from the same commit, so the two cannot drift. The only differences are the owner's personal settings (who they are, their addresses, their account ids), swapped for examples, and a check refuses to publish if any personal detail is left in.
